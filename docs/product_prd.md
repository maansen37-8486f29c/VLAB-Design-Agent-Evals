# 产品需求简述（PRD）

## 1. 问题与用户
V·LAB车辆设计教学中，学生需要获得初步、可解释的设计评审意见，但大模型可能忽略项目硬性约束、编造工程参数或输出过长内容。

主要用户：车辆设计方向学生；辅助用户：教学评审人员。

## 2. 目标
- 根据问题识别关键设计风险与约束冲突；
- 对项目专有要求优先检索知识库并给出需求编号；
- 对缺失尺寸/标准保持谨慎；
- 通过测试集与版本对比评估响应质量。

## 3. 产品边界
- 非实车安全认证、非国家标准查询权威系统；
- 当前知识库是一份明确标记的练习材料；
- 自动规则工具只识别有限关键词模式；
- Dify Agent 的线上RAG-002/003测试因额度不足尚未执行。

## 4. MVP功能
1. 车辆设计描述输入；
2. 结构化设计初评；
3. RAG项目规则检索；
4. 规则查询与硬约束冲突检查函数（离线原型）；
5. 测试结果和Bad Case台账。

## 5. 验收指标（目标，不是实际达成结果）
| 指标 | 定义 | 当前状态 |
|---|---|---|
| 项目规则准确引用率 | 编号、内容均正确的检索案例 / 有标准答案的检索案例 | 仅RAG-001人工初验 |
| 硬性约束识别率 | 应命中的硬约束中正确命中的比例 | 线上Agent待扩充测试 |
| 证据边界遵循 | 不编造未提供的工程参数和法规条款 | 已做部分人工测试，样本小 |
| Bad Case闭环 | 问题→归因→修复→同题复测 | Prompt迭代中已实践 |

## 6. 后续里程碑
- 完成RAG-002/003真实线上复测；
- 将本地规则校验代码部署成HTTP接口、配置Dify自定义API工具，并验证真实调用日志；
- 扩展覆盖20+条样例，补充失败用例和重复测试；
- 完善研发协作、迭代报告和可复现部署说明。
